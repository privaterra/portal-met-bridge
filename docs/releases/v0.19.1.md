**portal-met-bridge 0.19.1 — alpha.** Meticulous & Belka Portal conductivity data visualization & analysis: a local web app that records a [Belka Portal](https://www.belka.coffee/)'s conductivity stream alongside a [Meticulous](https://meticuloushome.com/) espresso shot, integrates it against the scale, and reviews the result.

**0.19.1 is the first release of the 0.19 changes.** The v0.19.0 tag exists but never got a release: its build workflow had a mistake, and GitHub had no macOS runner free that hour. Nothing in the app differs between the two; if you run from source at v0.19.0 you already have everything below.

**A security release — please update.** Nothing new to click; what changed is who the app's small server listens to, what the page will run, and how the libraries it ships are kept current. Everything in [0.18.0](https://github.com/privaterra/portal-met-bridge/releases/tag/v0.18.0) still holds, including that the Portal driver has not yet been proven on the author's own Portal.

## What was wrong, and what changed

- **A website you visited could reach the app.** The local server answered any request, whatever page sent it. A page elsewhere could have stopped the server, written files into the data folder, or — through the machine relay — started a brew. Nobody is known to have done so. The server now refuses requests a browser marks as coming from another site, and answers only to names that cannot be made to point at your network from outside (addresses, `localhost`, `.local` and other LAN names, its certificate's names).
- **The PDF library was two major versions old.** jsPDF 2.5.2 had twelve published advisories, two critical. The parts they concern are not the parts the app uses, but nothing would have warned anyone if one had been. It is now 4.2.1, with no open advisory. The other four libraries (uPlot, socket.io-client, qrcode-generator, fflate) were already current.
- **The page now runs under a Content-Security-Policy** (`script-src 'self'`): even text that slipped past the escaping could not run as script. Three places did slip past and are fixed: the **profile name** in the Analysis tab's *What the review will read* panel (a profile shared by someone else with markup in its name would have run in the page), and a shot id and a file name in History (reachable only through a crafted backup). Restored backups are now normalised before they are stored.
- **A settings file can no longer change where your API key is sent.** Importing settings leaves the *OpenAI-compatible endpoint* alone and says so; the field warns when an endpoint is plain http on another computer.
- **Files from the data folder download instead of opening in the page**, the server serves only the app's own files (not `.git/`, tests or tools), follows no symlinks out of the data folder, and the relay no longer passes cookies or security headers in either direction.
- **Fixed:** reviews in a restored backup now appear at once (before: after a reload).

[SECURITY.md](https://github.com/privaterra/portal-met-bridge/blob/v0.19.1/SECURITY.md) has the full review — eleven findings with severities — the trust model, and how to report a problem privately.

## You may notice

- **"421 — this server does not answer to the name …"** if you open the page by a public name (DuckDNS, a reverse proxy, a Tailscale `.ts.net` name). List the name: `ALLOWED_HOSTS=name node serve.mjs`, the same line in the macOS app's config file, or the Home Assistant option `allowed_hosts`. `localhost`, IP addresses, `homeassistant.local` and the like need nothing.
- **Importing settings** no longer fills in the OpenAI-compatible endpoint; type it yourself.
- Links to files in the server's data folder download.

## Libraries are now tracked

Every file in `vendor/` is recorded in `vendor/manifest.json` with its package, version and SHA-256, and the tests verify them. `npm run deps` reports newer versions and security advisories for exactly what is shipped; `npm run deps:update` fetches the latest. On GitHub the same check runs on every push, blocks a release while a shipped library has a high or critical advisory, and every Monday a workflow fetches the latest versions, runs the tests and opens a pull request. Dependabot alerts now see the shipped libraries too. The same weekly run watches the projects the Portal and machine protocols come from.

## Install

**macOS — the app (no terminal).** Download `portal-met-bridge-0.19.1-macos.zip` (or the `.dmg`), move *Portal Met Bridge.app* to Applications (replace the old one) and open it. Your shots, beans, reviews and settings are kept: they live in the browser and in `~/Documents/portal-met-bridge`. It runs on Apple silicon and Intel, starts its own small server on `http://localhost:8787` and opens Chrome. It is not signed: the first time, right-click → Open.

**Home Assistant on a Raspberry Pi 5 (or any Home Assistant machine).** Settings → Apps → Portal Met Bridge → **Update** (or add the repository `https://github.com/privaterra/portal-met-bridge` and install). The image is rebuilt on the device with current Alpine packages.

**From source.**

```sh
git pull               # or: git clone https://github.com/privaterra/portal-met-bridge.git
./start.command        # macOS: serves http://localhost:8787 and opens Chrome; or: node serve.mjs
```

Reload the page once after updating (the old page is cached with the old version stamp).

## Known limits (please read)

- **No login, by design.** On a Mac the server listens on `localhost` only; in Home Assistant it is open to your LAN, like the machine's own API. Do not forward its ports to the internet.
- **The Portal driver is untested on a physical Portal by the author.**
- **EC is not TDS**; TDS/EY are estimates from your own refractometer readings.
- **The AI review reads numbers**, not the cup.
- **Unsigned macOS app; Home Assistant builds on the device.**
- The security review was done **by the same AI assistant that wrote the code**, reading every file and testing each fix; it is not an independent audit. Reports are welcome — *Security → Report a vulnerability*.
