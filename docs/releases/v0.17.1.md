**portal-met-bridge 0.17.1 — alpha.** Meticulous & Belka Portal conductivity data visualization & analysis: a local web app that records a [Belka Portal](https://www.belka.coffee/)'s conductivity stream alongside a [Meticulous](https://meticuloushome.com/) espresso shot, integrates it against the cup weight, estimates TDS from your own refractometer readings, reviews shots with an AI model of your choice, hands the brew to Beanconqueror, and shows a machine dashboard. Runs on your Mac (or a Raspberry Pi) and talks to the Portal and the machine from Chrome; nothing leaves your network except the AI review you ask for.

This is **0.17.0 with its macOS build fixed** — the v0.17.0 tag never got a release because the packaging script failed on the build runner — plus three small fixes. Everything in the [0.17.0 notes](https://github.com/privaterra/portal-met-bridge/blob/v0.17.1/docs/releases/v0.17.0.md) (ratings and comments, the AI review inside the PDF report, continued long reviews, stage-by-stage verdicts, the new tagline) ships here for the first time as a download.

## What changed since 0.17.0

- **The macOS app builds again.** `tools/package-macos.sh` read a variable before assigning it when it bundled a Node runtime — a path only the release runner took — so the v0.17.0 workflow stopped at *Build the app*. Fixed, and the unit tests now build the bundle with stand-in runtimes on every run. The script also takes `--arch arm64` for an Apple-silicon-only build; [docs/RELEASING.md](https://github.com/privaterra/portal-met-bridge/blob/v0.17.1/docs/RELEASING.md) is the new step-by-step for making a release and attaching the package.
- **Analysis → Review shots with AI**: a rated shot's row in the shot picker no longer breaks onto two lines; the ★ rating sits among the row's tags.
- **Hardening from code scanning.** The Machine tab now escapes everything the machine's API answers (Wi-Fi name, gateway, MAC, health note, profile names, statistics) before showing it, treats counts as numbers, and accepts only a plain colour for a profile's accent — a hostile or compromised machine on your network could otherwise have run script in the page (CWE-79). CSV exports neutralize fields that a spreadsheet would run as a formula (a value starting with `=`, `+`, `-`, `@` or a tab gets a leading apostrophe; numbers are untouched — CWE-1236).

## Install

**macOS — the app (no terminal).** Download `portal-met-bridge-0.17.1-macos.zip` (or the `.dmg`), move *Portal Met Bridge.app* to Applications and open it. It runs on Apple silicon and Intel (both Node runtimes are inside), starts its own small server on `http://localhost:8787`, keeps your files in `~/Documents/portal-met-bridge`, and opens Chrome. This alpha is **not signed or notarized**, so macOS stops it the first time: right-click (control-click) the app → **Open** → **Open**, or System Settings → Privacy & Security → **Open Anyway**. Once is enough. Chrome or Edge is required for the Portal's Bluetooth link. Upgrading from an earlier app: replace it; your shots live in Chrome's database and your files in `~/Documents/portal-met-bridge`, both untouched.

**Home Assistant on a Raspberry Pi 5 (or any Home Assistant machine).** Settings → Apps → *Install app* → ⋮ → *Repositories* → add `https://github.com/privaterra/portal-met-bridge` → install **Portal Met Bridge** → Start (or press **Update** on an installed 0.16 / 0.17). The page is at `http://homeassistant.local:8787`, Bluetooth needs the https address `https://homeassistant.local:8788` with its certificate trusted once (the http page links to the certificate and the steps), and the files go to `/share/portal-met-bridge`. Details: [docs/PACKAGING.md](https://github.com/privaterra/portal-met-bridge/blob/v0.17.1/docs/PACKAGING.md).

**From source.**

```sh
git clone https://github.com/privaterra/portal-met-bridge.git
cd portal-met-bridge
./start.command        # macOS: serves http://localhost:8787 and opens Chrome; or: node serve.mjs
```

**You need**: Chrome or Edge (Web Bluetooth); a Meticulous on your network (its API is on port 80 — enter the machine's IP or `meticulous.local` under Settings → Machine); the Belka app on your phone closed (the Portal takes one connection at a time); a refractometer only if you want TDS/EY estimates; an API key from Anthropic, OpenAI or Google only if you want AI reviews (the README says how to get one).

## Known limits (please read)

- **The Portal driver is untested on a physical Portal by the author.** It is written from the [variegated-rs](https://github.com/variegated-coffee/variegated-rs) driver and the [Decenza](https://github.com/janhcla/Decenza) spec and verified against a simulated Portal only. The **Connection check** under the Connect button shows each step so a failure says where.
- **EC is not TDS.** The Portal measures conductivity; TDS/EY are estimates from your own refractometer readings and shift between coffees, waters and mountings. Treat *mean EC per gram* as the primary number.
- **The AI review reads numbers.** It cannot taste the cup — that is what your rating and comment are for — or see the puck; check any figure it quotes against the *Stages, from the recording* table, and test its suggestions one at a time.
- **Unsigned macOS app; Home Assistant builds on the device** (a minute or two on a Pi 5).
- Tested against Meticulous firmware 0.2.24 (beta channel); other versions may name stages or fields differently. Web Bluetooth has no background mode: keep the tab open while pulling shots.
- The code was **written by an AI assistant from the author's descriptions** (see *How this was built* in the README) and has had one pair of eyes on it.

## What would help most

Open an [issue](https://github.com/privaterra/portal-met-bridge/issues) with a session against a real Portal (Settings → Logging and debug → log on, with packets, then the `.log` and the Connection check's steps), refractometer readings next to the app's ∫EC dm for a few shots of one coffee, or anything the machine's API answered differently.
